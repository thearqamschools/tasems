# Decisions log

Every architectural or scope decision is recorded here with its date, the options considered and the reason.
Approved decisions are not changed silently: a change gets a new entry that supersedes the old one.

Decision authority: the project lead at The Arqam Schools (Samanabad head office), per the master plan.

| ID | Date | Decision | Reason | Status |
| --- | --- | --- | --- | --- |
| D-001 | 2026-10-16 | Modular monolith: one application, strict internal modules (apps), one PostgreSQL database | Lowest cost and complexity for the scale (250,000+ students); modules can be split out later if one proves to need it | Approved (master plan) |
| D-002 | 2026-10-16 | Stack: Python 3.12 + Django 5.2 LTS + PostgreSQL 16. Staff screens server-rendered (Django templates + HTMX); parent app as an installable web app (PWA) later | **Supersedes the master plan's Next.js + NestJS recommendation.** The in-house team is one senior developer; Django gives login, permissions, migrations, admin, translations (Urdu) and security defaults built in, so one person can maintain it. Python is also the strongest ecosystem for the AI work (RAG, OCR). Django 5.2 is a long-term-support release | Approved — stack choice delegated to Claude by the project lead |
| D-003 | 2026-10-16 | Code lives in a private GitHub repository owned by The Arqam Schools | Ownership, history, automated testing (GitHub Actions) | Approved |
| D-004 | 2026-10-16 | MVP scope: platform core, organisation and student records, student attendance, Daily Diary, AI Teacher Assistant, basic head-office dashboard | Daily value for teachers and parents, low financial risk | Approved |
| D-005 | 2026-10-16 | Pilot at the Faisalabad head office campus (Samanabad) first, then volunteer Faisalabad-region franchises; Lahore after Gate 2 | Company-owned campus, close supervision | Approved |
| D-006 | 2026-10-16 | Branch isolation: every branch-owned table has `branch_id`; all reads go through `Model.objects.for_user(user)`. PostgreSQL row-level security is the second lock | Two independent locks on branch data | Approved; RLS built in Milestone 1f |
| D-007 | 2026-10-16 | Access = roles × scopes. A role is a bundle of permissions; it is assigned at network, head office, region or branch scope. Head office responsibilities are data, not code | Matches the Faisalabad/Lahore split and franchise structure; no hard-coded head office rules | Approved |
| D-008 | 2026-10-16 | Append-only audit log of every create, update, delete, login and failed login, with before/after values; passwords never logged | Accountability for student and financial records | Approved |
| D-009 | 2026-10-16 | Students have no logins; parents will | Project lead decision | Approved |
| D-010 | 2026-10-16 | Royalty is a per-branch percentage, default 8% for franchises, 0% for company-owned campuses | Head office takes 8% of monthly fee collections from franchises; per-branch field allows exceptions without code changes | Approved |
| D-011 | 2026-10-16 | Staff attendance is imported from the existing face-recognition biometric machines, not replaced | Machines already in use; brand/model and export method to confirm | Approved |
| D-012 | 2026-10-16 | The built-in Django admin is used only as a temporary back-office for head office and IT during early milestones. Teachers, principals and parents get purpose-built screens | Fast, secure setup screens now; proper user experience where it matters | Proposed |
| D-013 | 2026-10-16 | Seed data contains only confirmed facts (head offices, Samanabad campus, roles, class levels). Lahore address, regions, subjects and session dates are entered by head office | Accuracy rule: nothing invented | Approved |
| D-014 | 2026-10-16 | Class structure: Early Years = Play Group, Nursery, Prep; Primary = Class 1–5; Middle School = Class 6–7; High School = Class 8, Pre-9, Class 9, Class 10; plus Hifz-e-Quran | Confirmed by the project lead | Approved |
| D-015 | 2026-10-16 | From Middle School (Class 6) onwards boys and girls are separated: each section is marked Boys or Girls, and a student can only be enrolled in a section of their own gender. Early Years and Primary sections may be mixed | Boys and girls campuses separate from Middle School (project lead) | Approved |
| D-016 | 2026-10-16 | Separate boys and girls buildings are Campuses inside one Branch. Administration, admissions, fees and the principal stay at branch level; a section can be placed in a campus, which must match its gender group | Confirmed by the project lead: one branch, two buildings, one administration and fee point | Approved |
| D-017 | 2026-10-16 | Two-step sign-in uses authenticator apps (TOTP) with backup codes, not SMS codes | Free, works without mobile signal, no SMS gateway contract; SMS can be added later if staff need it | Approved |
| D-018 | 2026-10-16 | Lockout is counted from the audit log rather than server memory | Works correctly when several server processes run; no extra service needed | Approved |
| D-019 | 2026-10-16 | Staff screens are server-rendered pages with one small stylesheet and no JavaScript framework | Fast on slow connections, easy for one developer to maintain | Approved |
| D-020 | 2026-10-16 | Student attendance is taken once a day per section (confirmed by the project lead). Statuses: present, absent, leave, late; late counts as attended | Matches current practice | Approved |
| D-021 | 2026-10-16 | Class teachers can mark only their own sections and only for today; principals and academic coordinators correct past days, and every correction is audited | Keeps registers honest while allowing genuine corrections | Proposed |
| D-022 | 2026-10-16 | Attendance rows are written in bulk; the section register (with totals) is what dashboards read | One row per student per day is ~50 million rows a year nationally; dashboards must not scan it | Approved |
| D-023 | 2026-10-16 | School week: Sunday off for all; on Saturday only Hifz, Pre-9, Class 9 and Class 10 attend. Stored per class level (`attends_on_saturday`), so head office can change it without code. Hifz attendance is also once a day | Confirmed by the project lead | Approved |
| D-024 | 2026-10-16 | Diaries are rendered to PDF with WeasyPrint (Pango/HarfBuzz shaping) and to a WhatsApp image from that PDF; fonts (Noto Nastaliq Urdu, Noto Serif) are bundled | Correct Urdu Nastaliq shaping with no browser needed on the server; same output on every server | Approved |
| D-025 | 2026-10-16 | One diary per section per day; layout copied from the Class 4 diary shared by the project lead | Matches current practice; boys/girls sections from Class 6 get their own diaries | Proposed |
| D-026 | 2026-10-16 | AI provider for the Teacher Assistant: Anthropic Claude API, billed separately from the claude.ai plan. Billing set-up later | Project lead decision | Approved |
| D-027 | 2026-10-16 | Milestone 1e (AI Teacher Assistant) deferred until textbook PDFs are collected; pilot hardening (1f) done first | Textbooks not available yet (project lead) | Approved |
| D-028 | 2026-10-16 | Row-level security is enforced only inside signed-in web requests; background jobs and commands run unrestricted. The app must connect as an ordinary role (`tasems_app`); `check_security` verifies this | A superuser connection silently ignores row-level security | Approved |
| D-029 | 2026-10-16 | Pilot hosting: one server with Docker Compose, Caddy for HTTPS, nightly encrypted backups copied off the server; managed PostgreSQL with point-in-time recovery before wider rollout | Low cost and simple for one developer; meets pilot needs | Proposed |
| D-030 | 2026-10-16 | Result pattern, every subject out of 100: Final exam 50, Mid-Term exam 25, Attendance 5 (automatic: 95%+ = 5, 90 = 4, 85 = 3, 80 = 2, 75 = 1), Discipline 5 (same in all subjects), Neatness 5, Summer vacation work 5, Class work & homework 5. Papers are marked out of their own totals and converted | Approved by the project lead; class work & homework added to reach 100. Stored as data (Setup → Grading schemes) | Approved |
| D-031 | 2026-10-16 | Pass = 33% of the subject total AND 33% of exam marks; grades A+ 80, A 70, B 60, C 50, D 40, E 33, F below (Punjab board bands); positions 1st–3rd only, ties share a position; Mid-Term absence with leave lets the Final cover its share, without leave counts as zero; an excused Final means no annual result until a re-sit | Behaviour marks cannot carry a failed paper; parents already know the board grades | Approved with D-030 |
| D-032 | 2026-10-16 | Result card designed by TASEMS (no existing template): one A4 page per student; Mid-Term progress report shows real marks; annual card shows every part of the pattern per subject | The school had no fixed template | Proposed |
| D-033 | 2026-10-16 | Fees are kept as a ledger: every amount owed is a charge (one fee head, one month), every amount received is a payment; the balance is charges minus payments. A voucher is the printed bill. Nothing is overwritten: wrong charges are cancelled and wrong payments reversed, with a reason, and audited. Payments pay the oldest charges first | Exact, traceable money records; part payments, several months together, arrears and advances all work the same way | Proposed |
| D-034 | 2026-10-16 | Samanabad fees: monthly fee 4,300, brothers and sisters 4,000; annual charges once a year in April — Play Group to Class 8: 4,500, Pre-9, 9 and 10: 5,500, Hifz: 2,000; admission 6,500; registration 1,500; summer vacation work charged with the July fee, amount set each year; late fine Rs 200 after the 10th. Each franchise sets its own fees (per-branch rates) | Confirmed by the project lead. Stored as data (Setup → Fee rates) | Approved |
| D-035 | 2026-10-16 | Sibling fee: children with the same father's CNIC in the same branch. The child admitted first pays the full fee, the others the sibling amount. A special discount and the sibling fee are not added together; the student gets whichever is cheaper | CNIC rule confirmed by the project lead; who pays the full fee and the "not added together" rule are TASEMS's proposal | Proposed |
| D-036 | 2026-10-16 | Due date is the 10th; vouchers made after the 10th are due the day they are made, and the person making them can choose another date. An unpaid voucher's balance moves to the next voucher and the Rs 200 fine is added once for each voucher not paid in full by its due date | Confirmed by the project lead ("one fine per unpaid month") | Approved |
| D-037 | 2026-10-16 | Special discounts apply only after approval by the principal or a director (branch owner, regional director, head office); the person who asked cannot approve their own request | Approval rule confirmed by the project lead; the four-eyes rule added by TASEMS | Approved (four-eyes rule proposed) |
| D-038 | 2026-10-16 | Voucher numbers are one sequence across the whole network (Setup → Voucher counter), so a Voucher ID identifies one voucher anywhere; the starting number can be set above the old system's last number | JazzCash and Bank Alfalah look vouchers up by Voucher ID | Proposed |
| D-039 | 2026-10-16 | Until the bill-payment connection used by JazzCash and Bank Alfalah is moved to TASEMS, online and bank payments are recorded by staff with the transaction ID (required). Bank name, account title and number are entered in Setup and never kept in code | The current software is already connected to those apps through a provider not yet identified | Proposed — provider to be confirmed by IT |
| D-040 | 2026-10-16 | Franchise royalty is worked out on the monthly (tuition) fee received during the month, at the branch's royalty percentage; monthly fee billed is shown alongside | "8% of monthly fee" could mean billed or received; received is what the franchise actually has | Proposed — to confirm |
| D-041 | 2026-10-16 | Until confirmed, Hifz, Pre-9, Class 9 and Class 10 use the same monthly fee as other classes (4,300) and no re-admission fee amount is set | Not yet provided; a class's own rate can be added in Setup without code changes | Proposed |
